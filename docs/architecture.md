# アーキテクチャ

利用者から見える動作、制約、対応範囲は[仕様](specification.md)に定義します。  
画面の視覚表現は[デザイン](../DESIGN.md)、セキュリティ方針は[セキュリティ](security.md)、検証方法は[テスト](testing.md)に定義します。  
このドキュメントでは、それらを実現するモジュール境界、状態管理、永続化を説明します。  

## モジュール構成

Tauri Coreプロセスの`Workspace`をGit操作の境界とします。  
フロントエンドは型付けされた`attach`、`detach`、`query`、`preview`、`execute`、`cancel`だけを利用し、Gitコマンド、パス解決、出力解析、世代管理、確認トークン、操作復旧を知りません。  
リポジトリを開く処理は、選択したパスを解決する`Open`、登録済みリポジトリを再接続する`OpenExisting`、リモートから作成する`Clone`へ分けます。  

`Workspace`内部には起動時に固定したGitツールチェーン実行器、状態とパッチの解析器、競合セッション、操作記録を置きます。  
これらはフロントエンドのインターフェースへ公開しません。  
同じリポジトリを再接続した場合はイベント用チャンネルを置き換え、古いウィンドウセッションへの重複通知を防ぎます。  

`RepositoryAvailability`問い合わせは登録状態を変更せず、場所を`available`、`missing`、`notRepository`、`inaccessible`へ分類します。  
フロントエンドは登録済みの場所を起動、復帰、一覧表示時に検査し、開いているリポジトリは通常更新の失敗後にも再検査します。  
設定には最後に選択した登録済みリポジトリのパスを保存し、起動時の検査結果が`available`の場合だけ`OpenExisting`で再接続して履歴画面へ移動します。  
通常用と開発用のメインウィンドウは非表示で生成し、起動時の場所確認と再接続を合わせて10秒で打ち切ります。  
判定結果に応じた履歴または一覧のDOMを確定してから、メインウィンドウを一度だけ表示し、期限後に完了した処理の結果は画面、ワークスペース、設定、通知へ反映しません。  
`VITE_E2E=true`ではフロントエンドから表示せず、WebDriverがウィンドウの表示状態を管理します。  
未保存内容がなければ`detach`し、既存の`repositoryRemoved`通知で作業画面から外します。  
未保存内容がある場合は`UnsavedChangesHandle`から種類、相対パス、基準ハッシュ、下書きを取得し、新しいセッションの内容と基準ハッシュが一致した場合だけ保存操作へ渡します。  
場所の付け替えは、登録情報、表示名、選択状態、リモート警告、両形式のコミット下書きを1つの設定更新で移します。  

`Remotes`問い合わせは`git remote`と`git remote get-url --all`からフェッチURLとプッシュURLを型付きで返します。  
`SetRemoteUrl`は変更前のURLも確認トークンの照合対象に含め、プレビューと実行の間に設定が変わった場合は`previewMismatch`で停止します。  
Gitはシェルを介さず固定した引数配列で`remote set-url`を実行し、更新後に設定を読み直します。  
リモート警告の永続化はフロントエンドの設定境界で行い、リモート名、分類、失敗日時以外を保存しません。  
通常のGitエラー詳細は既存の一時的なエラー画面と活動に残します。  

`ToolchainManager`はフロントエンドの`localStorage`とは独立したネイティブ設定を、アプリの設定ディレクトリへ一括保存します。  
起動時に内蔵またはシステムを一度だけ解決し、`Workspace`はその`GitExecutor`だけを保持します。  
内蔵モードはアプリのリソース内にある`bin`、`libexec/git-core`、テンプレートを`PATH`、`GIT_EXEC_PATH`、`GIT_TEMPLATE_DIR`へ固定し、埋め込んだ固定マニフェストとバンドル内ファイルのSHA-256を照合します。  
システムモードは選択・検証済みのGit関連構成要素を優先し、ログインシェルを対話モードで起動して取得した利用者の`PATH`、OS標準ディレクトリの順で実行パスを構成します。  
シェルの標準出力は識別子間の`PATH`だけを採用し、環境変数全体は保持しません。  
取得が2秒以内に完了しない場合、起動に失敗した場合、または出力が不正な場合は、固定のシステムパスへ切り替えます。  
この`PATH`はアプリの起動時に一度だけ確定し、すべてのGit操作とGitフックへ共通して渡します。  
内蔵モードでは利用者のシェルを起動せず、アプリのリソース外にあるツールチェーンを混入させません。  

Git Flowは`git_flow`モジュール内で安全な要求から引数配列を組み立てるインターフェースを持ち、任意のオプションやリポジトリ外の設定範囲を受け取りません。  
git-flow-nextにはJSON概要出力用のフラグがないため、JSONの取得を試した後に同じ概要のプレーンテキスト出力を型付きの状態へ変換します。  
共有`.gitflow`はローカル設定と比較して一括出力し、同期に失敗した場合はローカル値を復元します。  

通常の定期確認に使う世代の指紋は、Porcelain形式の状態、変更された追跡対象ファイルの索引OIDとモード、作業ツリーのinode、モード、サイズ、mtime、ctime、ローカルとリモートの参照一覧から作ります。  
この確認では通常ファイルの本文を開きません。  
破壊操作のプレビューと実行では対象本文のSHA-256を再計算し、操作記録も構造化コミットの直前に保存した厳密な要約値と再照合します。  

## コミット入力

フロントエンドからRustへ渡すコミット入力は、1行の`plain`メッセージと構造化した`conventional`のタグ付き共用体です。  
Rustは`plain`の空文字、改行、NULと、`conventional`の型、スコープ、メッセージ、フッターを形式別に最終検証します。  
検証後はどちらもリポジトリ内の一時メッセージファイルへ書き込み、同じGitコミットとGitフックの経路を使用します。  
`Preferences`はアプリ全体の形式設定と、リポジトリごとに分離した両形式の下書きを保持します。  
旧形式の構造化下書きはConventional Commits形式へ移行し、設定値がない場合は通常形式を選択します。  

## 差分表示とファイル編集

通常の差分と、ベース↔現在側／ベース↔取り込み側の比較表示には`@pierre/diffs`を使います。  
通常ファイルと競合結果の編集にはCodeMirrorを使い、検索、行番号、構文強調、取り消し、やり直し、`Command-S`、大規模ファイル用設定をフロントエンドの`TextEditor`へ集約します。  
競合固有の選択、解決済みへの変更、リビジョン同期は`ConflictSurface`のラッパーに残します。  
`@codemirror/merge`とDiffsの試験的な編集機能と競合機能は使用しません。  

差分画面は左ペインの選択キーを単一選択と複数選択で共有し、複数選択時は各パスと領域の差分を並列取得してリポジトリ上の表示順で右ペインへ並べます。  
フロントエンドの`profileDiffPatch`は未切り詰め差分のバイト数、行数、最長行を集計し、1 MiB、20,000行、256 KiBのいずれかを超えた場合を軽量表示として扱います。  
複数差分は各プロファイルと合計値を判定し、軽量表示ではハード上限でない項目を初期折りたたみにします。  
履歴はコミット全体のプロファイルで初期折りたたみを決め、ファイルヘッダーを先に描画して本文と画像の読み込みを展開後へ遅延します。  
既存Rust側で切り詰められた差分は描画面へ渡さず、フロントエンドは警告とファイル全体操作だけを表示します。  
フロントエンドからRustへ渡す部分選択は、連続行を表す`lines`と差分内の順序を表す`hunk`のタグ付き共用体です。  
Rustはリポジトリの世代と差分のリビジョンを再検証し、選択したハンクのヘッダーと本文、または選択行から再構成した文脈なしのパッチを`git apply --check`後に索引へ適用します。  
ハンクのステージ解除は同じパッチを索引へ逆適用し、ハンクの破棄は作業ツリーへ逆適用します。  
いずれも追加行と削除行を1つの操作として扱います。  
ファイルヘッダーの追従設定は`Preferences`に保存し、差分画面では外側のスクロール領域、履歴画面ではDiffsの固定ヘッダー機能へ反映します。  
設定が無効な場合はヘッダーと差分本文を同じスクロールの流れに置き、有効な場合だけヘッダーを上部へ固定します。  
上限による開閉状態は差分ID、選択、コミットの変更で初期化し、設定やその他の永続領域へ保存しません。  

Gitの索引と作業ツリーをRust側の正とし、未保存の下書きだけをフロントエンドで管理します。  
通常ファイルの読み込みには`FileContents`問い合わせを使い、テキスト、改行形式、UTF-8 BOM、内容ハッシュ、リポジトリの世代を受け取ります。  
`SaveFile`操作は読み込み時の内容ハッシュを必須とし、保存直前に現在の内容を再度読み込んで外部変更を拒否します。  
既存の改行形式、UTF-8 BOM、ファイルモードを維持し、リポジトリ内パスの検証後は不完全な内容が残らないよう、同じディレクトリの一時ファイルを使って置き換えます。  
通常ファイルと競合結果は共通の`UnsavedChangesHandle`をアプリへ公開し、画面、ブランチ、リポジトリ、ウィンドウから離れる際の確認を同じ契約で処理します。  
リポジトリの世代が更新された場合は編集中ファイルのハッシュを再確認し、未編集なら再度読み込み、編集中なら下書きを置き換えず外部変更状態へ移します。  

通常ファイルは差分画面のスナップショットに存在するパスだけを対象とし、UTF-8、改行形式、NUL、Git属性、Git LFS、ファイル種別、サイズ、行数、最長行をRustで検証します。  
保存は作業ツリーだけを書き換えるため、ステージ済みファイルを編集しても索引は維持されます。  

保存と解決済みへの変更では、`sessionId`、パス単位の`conflictGeneration`、`contentHash`をRustで再検証します。  
選択時に検証した本文とブロック状態は、Rustのセッションにも上限付きのリビジョンとして保持します。  

フロントエンドとRustは同じ計算方法を使い、スナップショットを96 MiB、100件まで保持します。  
上限を超えた場合は古いものから削除します。  
フロントエンドは現在状態とRust側の最新基準点を保持し、Rustのスナップショットはブロックの範囲と状態だけを保存して置換本文を複製しません。  
フロントエンドの各取り消し・やり直し用スナップショットは、手動編集の基になった直近のRustリビジョンを`baseDocumentRevision`として保持します。  
Rustは既知のリビジョンと本文が完全一致すれば、本文とブロック状態を一緒に復元します。  
未知の手動下書きは、既知の基準リビジョンへ戻してから差分を同期します。  

## アプリの更新

Rust側の`app_update`モジュールがTauri Updaterを所有し、更新の確認、署名検証、ダウンロード、インストール、再起動を行います。  
フロントエンドへUpdaterプラグインの権限は公開せず、`app_update_check`と`app_update_install`だけをTauriコマンドとして公開します。  
確認済みの更新情報はRust側で保持し、インストール時に任意のURLや署名をフロントエンドから受け取りません。  

実行中のバージョンにプレリリース識別子があればプレリリース用の`latest.json`を参照します。  
識別子がなければ安定版用を参照します。  
自動確認の時刻管理と表示状態はフロントエンドが担い、macOSメニューの「更新を確認…」も同じ確認処理を呼び出します。  

通常のビルドでは更新用ファイルを作りません。  
リリース時だけ`tauri.updater.conf.json`を重ね、リポジトリ外の秘密鍵で`.app.tar.gz`へ署名します。  
更新用の`latest.json`はバージョン別のGitHub ReleaseにあるURLと署名を参照し、対象ファイルの公開が完了してから置き換えます。  

## 運用ライフサイクル

リポジトリを変更する操作はリポジトリ単位で直列化し、操作IDを付けます。  
クローンを含む長時間の操作はチャンネルイベントで開始、進捗、完了、失敗、キャンセルを通知し、フロントエンドの活動へ反映します。  
キャンセル時はGitのプロセスグループを停止し、すべての変更操作が終了した後は、フックの成否にかかわらずGitの実状態を再取得します。  
活動は現在のセッションの詳細と、直近1年分の復元済み要約を分けて永続化します。  
復元済み要約には件数上限を設けません。  
活動画面とRechartsのグラフは別々の遅延読込み単位とし、ワークスペース用のバンドルではRechartsを先読みしません。  
開発用ビルドでは、起動時のネイティブ実行ファイルのデバイス、inode、サイズ、mtimeを保持し、実行の直前に現在の実行ファイルと照合します。  
再ビルドによって実行ファイルが変わっている場合は、再ビルド前のTauri Coreプロセスで操作を続けず、アプリの再起動を求めます。  
配布用ビルドにはこの照合を含めません。  

マージ、リベース、チェリーピック、リバートの進行状態は、Gitの識別ファイルと最小限の操作記録から再構成します。  
チェリーピックとリバートの操作記録は、Git実行前の`preparing`と、適用結果を厳密な要約値付きで記録した`applied`を一括保存します。  
構造化コミットのフック失敗によって索引や作業ツリーが変更された場合は、プレビューで現在状態を再照合し、中止だけを許可する段階へ移ります。  
フックの失敗が状態を変えていなければ`applied`を維持し、段階を持たない旧形式の操作記録は要約値の有無から安全側に判定します。  

## 多言語境界

フロントエンドの固定文言はi18nextの言語別JSONカタログへ集約し、react-i18nextを通して表示します。  
日時と数値は`ja-JP`／`en-US`の`Intl`で整形し、複数形はi18nextへ委ねます。  
選択中の言語に文言がない場合でも別の言語へ切り替えません。  
言語変更はReactの`I18nProvider`を更新して全画面を再描画し、`html[lang]`とmacOSメニューも再起動なしで同期します。  
macOSメニューはフロントエンドと同じJSONカタログを読み込みます。  

Rustからフロントエンドへ渡す結果、進捗、プレビュー、競合ラベル、エラーは、翻訳済み文字列ではなくメッセージIDと型付き引数を持つ`LocalizedMessage`とします。  
活動の第2版も同じ構造を保存するため、表示中または保存済みの項目を言語変更後に再翻訳できます。  
旧形式の活動キャッシュはプレリリース用の30日間キャッシュであり、第1版から移行しません。  

## セキュリティ

脅威モデル、信頼境界、共通の安全性保証、機密情報、依存関係、検査方針は[セキュリティ](security.md)に定義します。  
各モジュールは同ドキュメントの保証を、上記の境界、入力検証、状態照合、権限制御として実現します。
