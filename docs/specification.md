# 仕様

このドキュメントでは、利用者から見えるアプリの動作、制約、対応範囲を定義します。  
画面の視覚表現は[デザイン](../DESIGN.md)、内部の実現方法は[アーキテクチャ](architecture.md)、共通の安全性方針は[セキュリティ](security.md)、検証方法は[テスト](testing.md)に定義します。  

## 対応環境

Apple Siliconを搭載したmacOS 26.0以降のMacに対応します。  
Intel MacおよびmacOS以外のOSには対応しません。  

## リポジトリ

### 登録と開始

Finderまたは絶対パスで選択した場所から、既存リポジトリのルートを探して開きます。  
選択した場所が既存リポジトリの配下なら、そのルートを開き、入れ子のリポジトリは作成しません。  
既存リポジトリが見つからない場合に限り、選択したパスへ`main`ブランチのリポジトリを作成します。  

既存のローカルリポジトリの登録とURLからのクローンは、共通の「リポジトリを追加」画面から行います。  
画面には「リモート」と「ローカル」のタブを表示し、初期状態では「リモート」を選択します。  
タブを切り替えても入力済みの値は保持します。  
リモートとローカルの入力値はそれぞれ独立して保持し、一方の入力で他方を変更しません。  
リモート名が未入力ならURL末尾の名前を、ローカル名が未入力ならパス末尾の名前を自動補完します。  
登録済みリポジトリがない場合も、空状態のカード内には共通の追加操作だけを表示します。  
リポジトリ一覧ページと設定ページでは、サイドバーの開閉、リポジトリの切り替え、ブランチの切り替えを表示しません。  
登録済みリポジトリがある場合は、一覧の上部左側にリポジトリアイコンと合計数、右側に検索欄と追加操作を表示し、一覧は10件を超えるとスクロールできるようにします。  
登録済み一覧の各項目はリポジトリ切り替え画面と同じ表示にし、現在のリポジトリはリポジトリアイコンの左にチェックを表示します。  
一覧を開いた時は先頭の項目を選択してフォーカスを置き、上下の矢印キー、Home、Endでは選択とフォーカスを一緒に移動します。  
一覧行の単一クリックでは選択状態だけを変更し、ダブルクリックでリポジトリを切り替えます。  
ホバー、フォーカス、選択、3点リーダーの展開時は、3点リーダーを含む行全体へ背景色を表示します。  
一覧の外枠は角丸にせず、選択状態を示す左端のアクセント線は表示しません。  
一覧には常にスクロールレールの幅を確保し、内容が表示領域を超えた場合は右端にスクロールバーを表示します。  
切り替え、リポジトリ情報の変更、削除は3点リーダーと右クリックで開く同じメニューにまとめ、確認や編集が必要な操作は一覧ページ上にダイアログで表示します。  
アプリの起動時は、最後に選択した登録済みリポジトリが利用可能ならそのリポジトリを開き、履歴画面を表示します。  
前回選択したリポジトリがない場合、または場所が利用できない場合は、リポジトリ一覧ページを表示します。  
起動先の判定と再接続が完了するまではメインウィンドウを表示せず、履歴またはリポジトリ一覧のDOMを確定した後に一度だけ表示します。  
判定と再接続は10秒で打ち切り、期限後はリポジトリ一覧ページを表示し、遅れて完了した結果や失敗は画面と状態へ反映しません。  
共通ヘッダーの設定の左には、日本語で「一覧」、英語で「Repository」と表示するリポジトリアイコン付きのボタンを置き、リポジトリ一覧ページへ移動できるようにします。  
リポジトリ一覧ページと設定ページでは履歴、差分、活動、一覧、設定を表示し、リポジトリが未選択の間は差分、履歴、活動を無効にします。  
「リモート」タブではリポジトリのURL、保存先の親フォルダ、リポジトリ名を入力し、入力したリポジトリ名を親フォルダへ連結してクローンします。  
URLから推測できる場合はリポジトリ名へ初期入力します。  
「ローカル」タブではリポジトリのパスと名前を入力し、既存リポジトリの登録または新規リポジトリの初期化を行います。  
保存先の親フォルダは直接入力するか、フォルダ選択アイコンから選択します。  
保存先の親フォルダは設定から絶対パスだけを保存でき、初期値にはmacOSの`~/Documents`を絶対パスへ解決して使用します。  

登録済み一覧から選択したパスが削除済み、またはGitリポジトリでなくなっている場合は、新規リポジトリとして初期化しません。  
新規作成、登録済みリポジトリの再接続、クローンに成功したリポジトリは、正規化したルートを登録済み一覧の先頭へ記録します。  
同じパスを再度開いた場合は重複させず先頭へ移動し、クローンしたか既存のローカルリポジトリを開いたかによる分類は行いません。  
旧形式の`recentRepoPaths`は読み込み時に登録済み一覧へ移行します。  

### 場所の復旧とリポジトリの削除

起動時、アプリへ戻ったとき、一覧または切替画面を開いたときに、登録済みの場所が有効なGitリポジトリか確認します。  
場所の消失、Gitリポジトリでなくなった状態、アクセス不能を区別し、一覧へ「場所を確認」「リポジトリを確認」「アクセス権を確認」を表示します。  
一覧表示のためにリモート通信や全体検索は行いません。  

移動先は自動推測せず、Finderから利用者が選び直します。  
新しい場所が有効なGitリポジトリであることを確認した後、以前の場所と新しい場所を並べた確認画面を表示し、同じリポジトリかどうかは自動判定しません。  
表示名、開いている場所、選択中の場所、リモート警告、通常形式とConventional Commits形式の下書きは、一度の設定更新で新しい場所へ移します。  
新しい場所が登録済みの場合は自動で統合せず、登録済みの方を開くか、以前の登録を解除します。  

未保存のファイル編集または競合編集がある場合は、すべての操作を停止し、場所の選び直しまたは編集内容の破棄を求めます。  
新しい場所の対象内容が編集開始時のハッシュと一致する場合だけ下書きを引き継ぎ、一致しない場合は上書きせず、以前の画面に編集内容を保持します。  
削除画面では、登録だけ解除するか、リポジトリのローカルファイルをゴミ箱へ移動するか選択できます。  
未保存内容は確認後に破棄し、Git操作中はどちらも実行できません。

### 外部変更の反映

外部で行われたGit操作とファイル変更は、アプリへフォーカスが戻ったとき、および2秒間隔の更新で検出します。  
HEADが変わらないブランチ更新とタグ更新も履歴へ反映します。  
破壊操作のプレビュー後に対象が変更された場合は、状態やファイルサイズが同じでも実行を拒否します。  

## 画面構成と移動

画面上部はペイン境界で分割せず、全幅の共通ヘッダーとして表示します。  
差分、履歴、活動では、サイドバーを開閉するアイコンだけのボタンをmacOSのウィンドウ操作ボタンから十分な間隔を空けて右に表示します。  
リポジトリ名とブランチ名は、サイドバー、リポジトリ、ブランチの順が判別できる間隔を空けて表示します。  
差分画面では、コミット、プル、プッシュ、フェッチを左ペイン下部フッターの右端へアイコンだけで表示します。  
コミットする変更がない場合は、右ペインの上部中央に「差分がありません」とグレーの文字で表示します。  
アイコンだけのボタンは、ポインターを合わせたときとキーボードフォーカス時に、操作名を共通デザインのツールチップで表示します。  
ステージ表示が「分割」の場合は、ステージ済みと未ステージを固定見出し付きの独立した一覧として常に表示し、変更がない一覧も件数0で残します。  
各見出しは左からチェックボックス、開閉ボタン、ラベルの順に表示します。  
両方の一覧は利用可能な高さを等分し、それぞれのファイルだけを個別にスクロールします。  
履歴画面では、検索ボックスを左ペイン下端の固定フッターへ、上下に余白が残る高さで表示します。  
活動画面では、指標と期間のコンパクトな選択欄を左ペイン下端の固定フッターへ右寄せで表示し、左ペインにリポジトリ分析、右ペインに操作一覧と操作詳細を表示します。  
差分、履歴、活動の固定フッターは、一覧または分析内容との間を1pxの線で区切ります。  
活動画面を開いたときは右ペイン先頭の操作を選択してフォーカスし、上下の矢印キーで操作の選択を移動できます。  
履歴、差分、活動、一覧、設定は共通ヘッダーに表示し、現在の画面だけを選択状態にします。  
リポジトリとブランチの切り替えは、リポジトリを開いた状態の差分、履歴、活動で表示します。  

差分、履歴、活動では左ペインを開閉でき、閉じた場合は右ペインを全幅で表示します。  
開閉状態は起動中の対象画面で共有し、次回起動時は開いた状態へ戻します。  
リポジトリ一覧ページは左ペインを持たず、全幅で表示します。  

### 選択状態

選択状態とキーボードフォーカスの視覚表現は、[デザイン](../DESIGN.md#一覧と選択状態)に定義します。  
履歴のコミットを上下の矢印キーで移動している間は、ポインターが静止している項目のホバー背景を表示せず、ポインターを動かすと通常表示へ戻します。  
差分画面のファイル選択背景は行全体の単一面として即時に切り替え、チェックボックス、ファイル情報、ファイルメニューの間で切り替え時差を設けません。  

### ダイアログ

通常のダイアログ、確認用ダイアログ、フォーム付きダイアログは幅580pxとし、タイトルと説明と閉じるボタンを持つヘッダー、本文だけをスクロールする領域、右寄せの固定フッターで構成します。  
閉じるボタン、背景のクリック、Escは同じキャンセル操作として扱い、処理中や場所修復が必須の状態ではすべて無効にします。  
フッターの操作はキャンセル、補助操作、主要操作の順に表示します。  
リポジトリとブランチの切り替え画面は検索欄を備えた配置と幅を維持し、閉じるボタンは表示せず、背景のクリックとEscで閉じます。  
ダイアログを開いたときは最初の操作対象へフォーカスし、閉じたときは起点へ戻します。  
重なったダイアログでは最前面だけにフォーカスを閉じ込め、IME変換中のEscでは閉じません。  
実行時エラーは共通のダイアログで1件ずつ表示し、詳細からGitの終了コード、標準エラー出力、標準出力を確認できます。  
利用者の判断で解消できる状態は、共通エラーダイアログではなく対象画面内に表示します。  

## コミット

差分画面のコミットからダイアログを開き、メッセージ入力欄へフォーカスを置きます。  
ステージ済みの変更がない場合もダイアログを開き、実行ボタンを理由付きで無効にします。  
コミットに成功した場合だけダイアログを閉じ、失敗時は入力内容を保持します。  
コミットメッセージの形式はアプリ全体へ適用し、初期値は「通常形式」です。  
通常形式の場合はプレースホルダーのない1行のメッセージ入力だけを表示し、空文字、改行、NULを拒否して前後の空白を除去します。  
Conventional Commits形式の場合はメッセージ、型、任意のスコープ、破壊的変更を入力し、形式を検証します。  
通常形式とConventional Commits形式の下書きはリポジトリごとに分けて保持し、コミット成功時は使用した形式の下書きだけを消去します。  
リポジトリのGitフックは設定にかかわらず実行し、フックが要求するメッセージ形式を迂回しません。  

ステージ表示が「なし」の場合は、Gitの無視対象を除くステージ済み、未ステージ、未追跡の全変更をコミット直前にステージしてコミットします。  

## プルとプッシュ

差分画面のプルとプッシュは毎回ダイアログを開いてから実行します。  
ダイアログを開くだけではフェッチしません。  
プルは現在のローカルブランチを固定表示し、ローカルに取得済みのリモートブランチを`origin/main`形式で表示して、追跡先を初期選択します。  
追跡先がない場合もプルを利用でき、プル先を変更しても追跡先は変更しません。  
プルが分岐を検出した場合はダイアログを閉じ、選択したプル先を既存のマージまたはリベースの案内へ引き継ぎます。  
「マージした変更をすぐにコミット」は既定で選択し、分岐後にマージを選んだ場合はGitの既定メッセージでマージコミットを作成します。  
選択を外した場合はコミット前のマージ状態で停止します。  

プッシュは現在のローカルブランチを送信元として固定し、リモートと送信先ブランチを指定します。  
既存のリモートブランチを候補に表示し、新しいブランチ名も入力できます。  
プルとプッシュのダイアログにある「ブランチを更新」は、選択中のリモートをフェッチし、リモートブランチ候補を再度読み込みます。  
送信先の初期値は追跡先、`origin/現在のブランチ名`、最初のリモートの順で決定します。  
追跡先がない場合だけ、プッシュ成功時に選択した送信先を追跡先として設定します。  
「安全に強制プッシュ（--force-with-lease）」は対象リモート追跡ブランチのOIDを期待値とし、追跡情報がない場合はリモートに同名ブランチが存在しないことを期待値とします。  
選択時は警告を表示しますが、実行ボタンの見た目は変更せず、追加確認も表示しません。  
「すべてのローカルタグをプッシュ」は、現在のブランチと全ローカルタグをすべて成功する場合だけ一括で送信し、既存タグを強制上書きしません。  
両チェックボックスはダイアログを開くたびに未選択へ戻します。  

プルまたはプッシュの成功時はダイアログを閉じ、失敗時は選択内容を保持します。  
起点のプルまたはプッシュダイアログは実行中も入力内容を保持して背面に残り、共通の進捗ダイアログは閉じられません。  
活動がキャンセル可能になった場合は、共通の進捗ダイアログから一度だけキャンセルを要求できます。  
Detached HEADの場合、Git操作の実行中、または未保存の編集がある場合は、プルとプッシュを利用できません。  

## 差分表示

通常の差分と、競合中のベース↔現在側／ベース↔取り込み側を表示します。  
差分の未切り詰め内容が1 MiBを超える、20,000行を超える、または最長行が256 KiBを超える場合は、軽量表示へ切り替えます。  
軽量表示の単一差分は初期状態で折りたたみ、展開後だけ表示します。  
複数差分は個別または合計がいずれかの上限を超えた場合、ハード上限に該当しない項目を初期状態で折りたたみ、ファイルごとに開閉できます。  
既存のRust側の5 MiB上限で切り詰めた差分は本文を表示せず、警告だけを表示します。  
切り詰めた差分では差分表示面、画像候補、画像プレビューを生成せず、差分画面のファイル全体の操作だけを利用できます。  
履歴コミットの差分全体が5 MiB以下でGit出力も完全な場合は、既存の一括表示と軽量表示上限を適用します。  
履歴コミットの差分全体が5 MiBを超えるかGit出力が切り詰められた場合は、本文を表示せず、第一親またはルートとの比較にある全ファイルの一覧をGit順で表示します。  
この場合は「コミット全体の差分が大きいため、ファイルごとに読み込みます。必要なファイルを展開してください。」と案内し、各ファイルを初期状態で折りたたみます。  
ファイルを展開したときだけ対象ファイルの差分を読み込み、読み込み中は操作を無効にして進行状態を表示します。  
読み込みに失敗したファイルは既存のエラー表示と折りたたみ状態へ戻し、再展開で再試行できます。  
個別ファイルの差分が5 MiBを超えるか切り詰められた場合は、そのファイルだけ警告を表示し、他のファイルの表示を継続します。  
差分画面の左ペインで複数ファイルを選択した場合は、選択中のすべての差分を右ペインへ一覧表示します。  
Gitがバイナリとして扱う画像とSVGをプレビューできます。  
画像プレビューボタンとファイルメニューの「画像をプレビュー」はSVGだけに表示し、PNGなどのラスタ画像は常にプレビューを表示します。  
内容差分のない名前変更は、WebKitで画像としてデコードできた場合だけプレビューできます。  
画像としてデコードできないバイナリでは、既存の案内を表示します。  
画像プレビューのレイアウトは設定から「インライン」または「左右に分割」を選択できます。  
初期値の「左右に分割」では変更前を左、変更後を右に並べ、「インライン」では変更前を上、変更後を下に並べます。  
各画像の透明部分を除いた明るさを判定し、暗い画像には白、明るい画像には黒のプレビュー背景を個別に適用します。  
画像の透明部分には、選択した背景に合わせた明暗のチェック柄を表示します。  
チェック柄は内側の余白を含むプレビュー枠全体へ表示します。  
画像はSVGを含む形式にかかわらず、プレビュー枠内の上下左右中央に配置します。  
追加または削除では変更前・変更後の見出しを表示せず、レイアウト設定にかかわらず存在する側の画像だけを横幅いっぱいの既存の枠内に表示します。  
SVGはプレビューを閉じると通常のテキスト差分を表示し、画像としてデコードできないバイナリは既存の案内を表示します。  
ファイル全体のステージとステージ解除は、左ペインのファイルまたはグループのチェックボックスから行います。  
ファイル行をステージ済みと未ステージの間でドラッグして移動する操作は提供しません。  
差分画面の右ペインでは、各ハンクの`unmodified lines`行の右端からハンク全体をステージ、ステージ解除、または破棄できます。  
各ハンクのヘッダー左端には、ハンク番号と対象行範囲を控えめな色で表示します。  
`unmodified lines`の文言は表示せず、差分行には`+`／`-`記号を表示します。  
表示と編集は先頭の余白、行高、行番号列、本文の開始位置を揃え、差分の背景色と記号だけを表示固有の表現とします。  
表示中の変更行または未変更行の本体を左クリックするか行番号を直接選択し、Shiftクリックすると同じ側の範囲を複数行選択できます。  
選択行は追加行の緑と区別できる青系の背景で表示します。  
右クリックメニューから、選択した連続行をステージ、ステージ解除、または破棄できます。  
同じメニューから選択行の本文をコピーできます。  
選択行へフォーカスがある場合は`Command-C`でも本文をコピーできます。  
未変更行を含む選択では、編集とコピーだけを利用できます。  
差分上のドラッグによる文字選択とコピーはできません。  
ハンク操作は追加行と削除行をまとめて適用し、行操作は同じ側の連続した変更行だけを対象とします。  
バイナリ、名前変更、コピー、モード変更、シンボリックリンク、サブモジュール、競合、Git LFS対象ファイル、複数ファイルを含む差分、および表示上限を超えた差分はファイル全体で操作します。  

## 差分画面内のファイル編集とリネーム

差分画面に表示されているファイルは、差分ヘッダーの鉛筆アイコンまたはファイル行のメニューにある「ファイルを編集」からアプリ内で編集できます。  
差分ファイルと鉛筆の共通トグルボタンには「ファイル編集切り替え」のツールチップを表示します。  
各ハンクの「ハンクを編集」と、選択行の右クリックメニューにある「選択した行を編集」からも同じエディターを開けます。  
ハンクまたは行から開いた場合は、対象ハンクまたは選択行の開始位置をエディター上端から25%の位置へ配置します。  
ファイル全体のエディターを表示し、入力欄へフォーカスを置きます。  
編集時は差分ではなく作業ツリー上のファイル全体を右ペインへ表示し、複数選択中は編集を実行した1件だけへ選択を絞ります。  
エディターの読み込み中は現在の差分を維持し、読み込み完了後に表示を切り替えます。  
リポジトリ全体を探索するファイルブラウザーは設けません。  

左ペインのファイル行をダブルクリックするか、左右ペインのファイルメニューで「ファイルをリネーム」を選ぶと、左ペインのファイル名を入力欄へ切り替えます。  
入力欄では同じディレクトリ内のファイル名だけを変更し、別のフォームやダイアログは表示しません。  
削除されたファイルでは「ファイルをリネーム」と「Finderで表示」を無効にし、ダブルクリックでも入力欄へ切り替えません。  
「変更を破棄」は有効にし、削除前のファイルを復元できるようにします。  
リネーム先が既に存在する場合は上書きしません。  

差分とエディターのヘッダーには、1つの共通トグルボタン内に差分ファイルと鉛筆のアイコンを並べ、差分ファイルを差分表示、鉛筆をファイル編集として扱います。  
差分では差分ファイル側、エディターでは鉛筆側を丸い背景で選択状態にし、画像プレビューと同じアニメーションで背景を左右へ移動させます。  
どちらのヘッダーにもファイルメニューを表示します。  
SVGの画像プレビューボタンにも同じ共通トグルボタンを使い、表示と非表示のアイコンを並べて選択中の側を示し、差分ヘッダーで差分ファイルと鉛筆の左に表示します。  
画像プレビューの共通トグルボタンには「画像プレビュー切り替え」のツールチップを表示します。  
ファイルメニューは「ファイルを編集」、「ファイルをリネーム」の順で先頭に置き、「画像をプレビュー」、「変更を破棄」、「ファイルを削除」と表記します。  
ファイルを編集中は「ファイルの編集を終了」、画像を表示している間は「画像のプレビューを終了」と表記し、どちらも有効なまま元の表示へ戻せるようにします。  
SVGでは左ペインと右ペインのファイルメニューにも同じ表示切り替えを用意し、編集中は画像プレビューボタンを表示したまま無効にします。  
PNGなどのラスタ画像には、画像プレビューボタンとメニュー項目を表示しません。  
行を選択したまま表示と編集を切り替えた場合は、選択位置へスクロールしてフォーカスを戻します。  
削除行から編集へ切り替えた場合は、置換された先頭行または削除箇所の直後に残る行へ移動し、末尾の削除では最終行へ移動します。  
編集画面では、ファイルの最終行を表示領域の上端までスクロールできます。  
エディターのヘッダーに「キャンセル」と「保存する」は表示しません。  
未保存中は「未保存」の文字を表示せず、左ペインと右ペインのファイル名の右へ黄色い点を表示します。  
エディターを閉じずに保存できるのは`Command-S`だけとし、自動保存、自動ステージ、保存とステージの一括操作は行いません。  
未保存の状態で鍵ボタンを選んだ場合は「キャンセル」、「保存せずに表示」、「保存して表示」から選択します。  
保存成功後はエディターに残り、保存によって対象が差分画面から消えた場合だけエディターを閉じます。  
保存失敗時は下書きを維持してエラーを表示します。  

ステージ済みファイルの保存先も作業ツリーだけであり、Gitの索引は変更しません。  
保存後に生じた未ステージの変更へ選択を移します。  
未保存中はステージ、ステージ解除、ハンクと行の操作、破棄、コミット、プル、プッシュ、フェッチ、外部アプリで開く操作を無効にします。  
エディターのファイルメニューでは、未保存中もパスのコピーとFinder表示を利用できます。  

「キャンセル」は下書きを破棄して表示へ戻ります。  
別ファイルまたは別画面へ移動する場合や、ブランチまたはリポジトリを切り替える場合は、保存、破棄、キャンセルを選択します。  
未保存内容がある状態でウィンドウを閉じる場合は、確認画面を表示します。  
外部変更を検出した場合は強制上書きを許可せず、下書きを維持してコピーまたは再読み込みを選択します。  

通常編集の対象は、UTF-8、LFまたはCRLFのどちらか一方、5 MiB以下、10万行以下、最長行256 KiB以下の通常ファイルです。  
未追跡、未ステージ、ステージ済み、名前変更後の現在パスを編集できます。  
次のファイルは編集できない理由を表示し、既存の競合ファイルは競合エディターで扱います。  

- バイナリまたはNULを含むファイル
- UTF-8以外、改行形式の混在、単独のCRを含むファイル
- Git LFS対象ファイル
- シンボリックリンク、サブモジュール、削除済みファイル
- サイズ、行数、最長行の上限を超えるファイル

## 競合編集

競合結果はアプリ内で編集できます。  
未保存の編集内容が外部変更と競合した場合は上書きせず、下書きを保持したまま再読み込みまたはコピーを選べるようにします。  
編集の基準リビジョンが不明な場合や履歴から削除されている場合は再読み込みを要求し、現在のブロック状態から推測しません。  
保存後は新しいセッションとして扱い、古い取り消しとやり直しの履歴を破棄します。  

ファイル全体の選択では、選択した側の実行可能ビットを適用し、両方を選んだ場合は現在側を正とします。  
解決済みにする際は作業ツリーの存在を再確認し、ファイルはステージ、削除結果はGitの索引から削除します。  
ステージに失敗した場合は、保存済みで未ステージの部分失敗として通知します。  

LFまたはCRLFのどちらか一方を使うテキストファイルだけをアプリ内の編集対象とします。  
次の内容は外部エディターで解消します。  

- 改行形式の混在
- 単独のCR
- Git属性でバイナリに指定されたファイル
- NULを含むファイル
- UTF-8以外のファイル
- 上限を超えるファイル
- シンボリックリンク
- サブモジュール
- 名前変更またはディレクトリとファイルの競合

Gitの`conflict-marker-size`を競合ブロックの解析と、解決済みにする直前の競合マーカー検査に使用します。  
競合マーカーのないテキストやバイナリは暗黙に解決済みとしません。  
アプリ内での保存、ファイル全体の選択、または外部エディターで開いた後の内容変更を確認してから、解決済みへの変更を受け付けます。  

## 活動

活動は設定の前に表示し、実行したGit操作と選択したリポジトリのコミット分析を確認できます。  
操作一覧には状態、操作、概要、日時、所要時間を表示します。  
現在のセッションの操作ではコマンド、終了コード、標準出力、標準エラー出力も確認でき、復元済みの操作は概要だけを表示します。  

コミット分析では、7日、30日、90日、180日、1年の期間でコミット、コントリビューター、ローカルブランチの先端を確認できます。  
グラフは高さ240pxで表示します。  
空、エラー、一部省略の状態を表示します。  
読み込み開始から1秒未満は文言、プレースホルダー、アイコンを表示せず、表示領域の寸法だけを維持します。  
1秒以上続く場合だけ、共通の回転アイコンを表示します。  
グラフのデータ表は常時表示し、期間、コミット、コントリビューター、ブランチを単位付きで表示します。  
90日は週単位、180日と1年は月単位で集約し、コントリビューターは日単位で重複を除きます。  

差分、履歴、活動の左ペイン幅は画面ごとに保存します。  
ペイン境界には1pxの線を表示し、5pxのドラッグ領域を維持します。  
ホバー中やドラッグ中も境界線の色は変えません。  

## 操作の実行と復旧

リポジトリを変更する操作はリポジトリ単位で順番に実行します。  
クローンを含む長時間操作は、開始、進捗、完了、失敗、キャンセルの状態を活動へ表示します。  
実行中の操作をキャンセルした場合はGitプロセスを停止し、その後のリポジトリ状態を再取得します。  
クローン、コミット、フェッチ、プル、プッシュ、ブランチのチェックアウト、切り替えを伴うブランチ作成、Git Flow、マージ、リベース、チェリーピック、リバート、リセット、続行、スキップ、中止は、開始直後から共通の進捗ダイアログを表示します。  
進捗ダイアログには操作名、対象リポジトリ名、活動の最新要約、値を持たないプログレスバーを表示します。  
進捗ダイアログは実行中とキャンセル中に閉じることができず、活動がキャンセル可能になった場合だけ一度だけキャンセルを要求できます。  
成功またはキャンセルで進捗ダイアログを閉じ、プルが分岐を検出した場合も閉じて既存のマージまたはリベースの案内へ移ります。  
対象操作が失敗した場合は進捗ダイアログを閉じず、同じダイアログにエラー詳細と閉じるボタンだけを表示します。  
リモート設定の保存後に自動で行うフェッチと、ステージ、ステージ解除、破棄、保存、リネーム、タグ作成、リモート設定、問い合わせ、プレビュー、アップデート確認などの対象外操作は従来の表示を使用します。  

マージ、リベース、チェリーピック、リバート中は、競合解消と続行、スキップ、中止以外の一般的な変更操作を受け付けません。  
例外として、マージおよび保留中の構造化コミットに必要なコミットは実行できます。  
アプリは自動続行と通常のステージまたはステージ解除を行いません。  

マージコミットをチェリーピックまたはリバートする場合は、履歴でメインラインの親を選択します。  
選択時は親の数と選択範囲を検証します。  
プレビューの影響パスと書き戻し衝突は、選択した親との差分を基準にします。  

再起動時はマージ、リベース、チェリーピック、リバートの進行状態を復元し、自動続行やロックファイルの自動削除は行いません。  
Git操作の開始記録だけが残っている場合や、構造化コミットのフック失敗によって索引や作業ツリーが変更された場合は任意のコミットを許可せず、中止だけを受け付けます。  

## 履歴の操作

履歴のコミット操作は、対象行の右クリックまたは3点リーダーから選択します。  
3点リーダーには「その他の操作」のツールチップを表示します。  
履歴の左ペインでは右端との間隔を確保し、右ペインではトグルボタンと同じ高さにしてコミットメッセージの上端に揃えます。  
画像を含むコミットでは、右ペインの各ファイルヘッダーに画像を表示し、SVGだけに画像プレビューボタンを表示します。  
テキストとバイナリが混在するコミットでは、画像プレビュー中も既存のテキスト差分を常に表示します。  
コミット全体が軽量表示の上限を超える場合は、各ファイルのヘッダーだけを初期表示し、ファイルごとに本文、画像、プレビューを開閉できます。  
コミット行をダブルクリックした場合は、そのコミットを指すローカルブランチのうち、現在のブランチ以外が一意ならチェックアウトします。  
候補が複数ある場合は、対象のブランチチップをダブルクリックします。  
操作別ダイアログで入力と対象コミットを確認し、「次へ」で影響のプレビューへ進みます。  
プレビューの最終ボタンには「ブランチを作成」や「マージを実行」など、実際に実行する操作名を表示します。  
各コミットのメタ情報は、左右のペインともコミットID、作成者、日時の順に表示します。  
履歴先頭の未コミットの変更を選択すると、差分画面へ切り替えます。  
履歴の右ペインのテキスト差分では、表示中の行または行番号をクリックし、同じファイル・同じ側をShiftクリックして連続行を選択できます。  
選択行の右クリックメニューには「選択した行をコピー」だけを表示し、選択本文を表示順に改行で連結してコピーします。  
選択中の差分面では`Command-C`でも同じコピーを行い、成功時は現在の言語の通知を4秒表示し、失敗時は現在の言語でエラーを表示して、選択を維持します。  
コミットを切り替えると選択とコピー用メニューを破棄します。  
この選択とコピーは軽量表示を展開したテキスト差分だけに適用し、切り詰め、バイナリ、画像プレビューでは利用できません。  
履歴の選択行メニューには編集、ステージ、ステージ解除、破棄を表示しません。  

履歴で選択したコミットから、軽量タグをローカルに作成できます。  
同名のタグは上書きせず、作成したタグはリモートへ自動でプッシュしません。  

## 差分の表示設定

変更の右ペインでは、複数ファイルを選択している場合だけファイルヘッダー左端へトグルを表示し、ファイル単位で差分を折りたたみ、再展開できます。  
通常の単一選択時は折りたたみトグルを表示せず、軽量表示の上限を超えた単一差分では表示します。  
上限による折りたたみの開閉トグルには、既存の日英の操作名と`aria-expanded`、`aria-controls`を付け、EnterまたはSpaceで操作できます。  
履歴の右ペインでは、ファイルヘッダー左端のトグルからファイル単位で差分を折りたたみ、再展開できます。  
設定の「ファイルヘッダーの追従」を有効にすると、差分のスクロール中もファイルヘッダーを右ペイン上部へ固定します。  
この設定の初期値は無効です。  

差分画面の左ペインに表示するファイル一覧は、設定から「ファイル名とパス」、「フルパス」、「ツリー」を選択できます。  
初期値の「ファイル名とパス」は、ファイル名と親ディレクトリのパスを2段で表示します。  
「フルパス」は、リポジトリからの相対パスを1段で表示します。  
「ツリー」はステージ区分ごとにディレクトリ階層を初期展開し、ディレクトリ単位で折りたためます。  
表示形式にかかわらず、一覧下部の固定フッターには変更ファイル数と追加・削除行数を表示し、複数選択中は選択ファイル数を表示します。  

## リポジトリとブランチの切り替え

リポジトリ一覧ページとリポジトリ切り替え画面では、現在のリポジトリ、現在のセッションで最近開いたリポジトリ、その他のリポジトリ名の文字順で表示します。  
リポジトリとブランチの切り替え画面では、現在の項目を一覧の先頭に表示して初期選択し、フォーカスを置きます。  
上下の矢印キーによる移動は一覧の先頭と末尾で停止し、反対側へ循環しません。  
リポジトリ切り替え画面の各項目には、リポジトリ名とパスだけを表示します。  
リポジトリ切り替えボタンには変更状態の黄色い表示を出さず、切り替え画面の各リポジトリでは変更ファイル数を3点リーダーの左に件数バッジで表示します。  
一覧領域は5項目分の高さを常に確保し、ブランチ切り替え画面は項目の取得完了後に表示して画面の高さを変えず、6項目以上は領域内をスクロールします。  
下部の追加・作成操作は一覧行と区別できる中立色のボタンとして右寄せで表示します。  
一覧行を単一クリックすると、グレー系の背景色で選択状態を表示します。  
フッター右端のアイコン付き「切り替え」はアクセントカラーで表示し、選択した項目へ切り替えます。  
選択した項目を利用できない場合だけ無効にします。  
現在の項目を選択している場合に押すと、切り替えずに画面を閉じます。  
Enterまたはダブルクリックでも同じ切り替え処理を実行します。  
ダブルクリック、右クリック、または3点リーダーから開く操作メニューでも直接切り替えられます。  
リポジトリの操作メニューでは、リポジトリの切り替え、リポジトリ情報の変更、リポジトリの削除を選択できます。  
ブランチは現在のブランチ、main、master、trunk、production、prod、staging、stage、develop、development、integration、release、その他のローカルブランチの順に表示します。  
基準ブランチは大文字と小文字を区別した完全一致で判定し、その他のブランチはGitから取得した順序を維持します。  
ブランチ切り替え画面ではローカルブランチを選択でき、画面下部の作成ボタンは作成元のブランチを選択するまで無効にします。  
作成ボタンまたは各ブランチの操作メニューから、選択したブランチを起点に新しいブランチを作成できます。  
切り替え画面のフッターボタンはフォーム内のボタンと同じ高さに揃え、「切り替え」以外は中立色の背景で表示します。  
履歴からブランチを作成する場合は影響のプレビューを確認して実行し、ブランチ切り替え画面の作成フォームでは影響のプレビューを表示せず、「作成」または`Create`で作成して切り替えます。  
ブランチの操作メニューでは、ブランチの切り替え、作成、削除を選択でき、現在以外のローカルブランチは確認後に削除できます。  
未マージのコミットがある場合は、削除対象のコミットを表示し、再確認してから削除します。  
リモートブランチには影響しません。  
未コミットの変更がある場合も、Gitが変更を保持できるときは、既存ブランチへの切り替えと新規ブランチの作成・切り替えを実行できます。  
進行中のGit操作がある場合は、ブランチの作成と切り替えを利用できません。  
この画面にGit Flowへの導線は表示しません。  

## アプリの更新

自動アップデート設定の初期値は有効です。  
有効な場合は起動時、起動中の1時間ごと、および前回確認から1時間以上経過してアプリへ戻ったときに更新を確認します。  
自動で行うのは確認だけで、ダウンロード、インストール、再起動は利用者が確認画面で選択した場合だけ行います。  

macOSのStellaメニューには「更新を確認…」を表示します。  
この操作は自動アップデート設定が無効でも使用できます。  
アルファ版、ベータ版、リリース候補版を使用中の場合は同じプレリリース系統の更新を受け取り、安定版を使用中の場合は安定版だけを受け取ります。  
安定版の公開時は、プレリリース利用者もその安定版へ更新できます。  

更新時に未保存の編集がある場合は、「保存して更新」、「保存せずに更新」、「キャンセル」から選択します。  
Git操作または活動の実行中は更新を開始できません。  
更新ファイルは組み込みの公開鍵で署名を検証した後にインストールし、完了後にアプリを再起動します。  

## 安全性

リセット、破棄、マージ、リベース、チェリーピック、リバート、中止では、書き戻すパスと未追跡内容をプレビューの検証対象に含めます。  
状態一覧へ現れない無視対象の内容や、未検証のディレクトリとファイルの衝突がある場合は、Git操作を実行しません。  
ブランチの切り替えと作成・切り替えでは、Gitの通常の安全判定に従ってステージ済み、未ステージ、未追跡の変更を保持します。  
切り替え先の内容と衝突する場合は操作を拒否し、現在のブランチと変更を維持します。  
Gitの無視対象になっている内容は上書きしません。  

`*`、`[`、`?`、`:(glob)`を含むファイル名はパスのパターンとして展開せず、対象のファイル名として扱います。  
活動には環境変数と標準入力を保存せず、コマンド出力は機密情報を除去して上限内に切り詰めます。  
状態、索引、参照、影響パスなど、安全判定に使うGit出力が上限を超えた場合は、部分結果で続行せず操作を拒否します。  

## 表示言語

画面およびアプリが生成する通知とエラーは、日本語と英語に対応します。  
トースト通知は、共通ヘッダー内の上下左右中央に表示します。  
通常の説明文、通知、エラーではプロダクト名を主語にせず、「アプリ」または`The app`と表記するか、主語を省略します。  
ウィンドウタイトル、Stellaについて、アプリケーションメニューなど、プロダクト名そのものを示す場所は対象外です。  
Stellaについてには、実行モードにかかわらず`Ver.`形式のバージョン、その直下に`YYYY/MM/DD`形式の日付、著作権者、Sustainable Use License 1.0を表示します。  
開発版と試験版は`0.0.0-dev`と起動日、配布版は`1.0.0 (2bd8ecf)`のようにビルド対象の短縮コミットIDを括弧書きしたバージョンとビルド日を表示します。  
表示ラベルがある入力欄にはプレースホルダーを重ねず、表示ラベルがない検索欄だけに検索対象を示すプレースホルダーを表示します。  
選択中の言語に固定文言がない場合でも、別の言語の文言は表示しません。  
内部エラーの原文は固定文言として表示せず、選択中の言語のエラー文を表示します。  
Gitの終了コード、標準エラー出力、標準出力がある場合は診断情報として原文のまま常に表示し、最大5行の領域内でスクロールできます。  
初回起動時はmacOSの優先言語が日本語なら日本語を選び、それ以外の場合は英語を選びます。  
設定画面で言語を変更した後は、選択した言語を保持します。  
リポジトリ名、パス、ブランチ名、コミット本文、Gitの標準出力／標準エラー出力など、Git、OSまたは利用者が生成した内容は翻訳せず原文のまま表示します。  
日本語表示の操作名は、コミット、ステージ、ステージ解除、差分、競合、リポジトリなどの自然な日本語で表示します。  
Git、Git Flow、HEAD、URL、GPG、Git LFS、Conventional Commits、UTF-8、LF、NULなどの固有名詞、規格名、識別子は原文を維持します。  

## 設定

設定画面は、幅200pxのカテゴリ一覧と、独立してスクロールする右側の詳細ペインで構成します。  
設定画面を開くたびに「一般」を選択し、カテゴリの選択状態は保存しません。  
設定項目は次の6カテゴリに分けます。  

- 一般：言語、自動アップデート
- 権限：リポジトリの保存先、ファイルとフォルダ権限の確認
- 外観：外観、フォントサイズ、画面用フォント、コード用フォント、分割位置の一括リセット
- 差分：ステージの表示、ファイルの表示形式、コミットメッセージの形式
- エディター：差分レイアウト、ファイルヘッダーの追従、行の折り返し、折り返す文字数
- Git：グローバル無視リスト、Gitツールチェーン

通常の設定項目は説明の右側に選択欄を表示します。  
分割位置のリセットは、差分、履歴、活動の位置を1つのボタンで初期値へ戻し、完了後に通知します。  
リポジトリの保存先、グローバル無視リスト、Gitツールチェーンは説明の下に操作欄を表示します。  
リポジトリの保存先とグローバル無視リストは横幅を最大560pxに制限し、Gitツールチェーンの選択欄は通常の設定項目と同じ220pxで表示します。  
アクセスできない登録済みリポジトリがある場合だけ権限カテゴリに警告を表示し、macOSの「ファイルとフォルダ」を確認する導線を表示します。  
アプリへフォーカスが戻った際に登録済みリポジトリの利用可否を再確認し、警告を更新します。  
言語、外観、自動アップデート、差分レイアウト、ステージ表示、ファイルの表示形式、コミットメッセージの形式、Gitツールチェーンは、すべて選択欄で選択します。  
ステージ表示は「分割」と「なし」から選択し、「なし」では変更のステージ移動用チェックボックスと行メニューのステージ移動操作を表示しません。  
差分レイアウトは「インライン」、「左右に分割」の順に表示します。  
コミットメッセージの形式は「通常形式」、「Conventional Commits形式」の順に表示し、変更を即時にコミットダイアログへ反映します。  
行の折り返しは初期状態では無効とし、設定から有効にできます。  
この設定は差分画面の差分とエディター、競合比較とエディター、および履歴の右ペインに適用します。  
折り返しを有効にした場合の初期値は120文字とし、指定した文字数で折り返します。  
有効／無効を選ぶ選択欄は、有効の選択肢を先に表示します。  

設定の「グローバル無視リスト」には、`.gitignore`と同じ書式を1行に1パターンで入力します。  
初期値は`.DS_Store`、`._*`、`Thumbs.db`、`[Dd]esktop.ini`とし、設定を空にした場合はアプリ独自のパターンを適用しません。  
この設定はアプリから実行するGitだけに適用し、利用者のGit設定や既存の共通無視ファイルを変更しません。  
既存の`core.excludesFile`または標準のXDG無視ファイルとアプリの設定をアプリ設定領域の有効無視ファイルへまとめ、リポジトリの`.gitignore`と`.git/info/exclude`も通常どおり適用します。  
外部から変更されたGitの共通無視設定は、アプリの次回起動時またはグローバル無視リストを次に保存した際に反映します。  

## Git実行環境

既定ではアプリに同梱したGit、Git LFS、git-flow-nextを使用します。  
設定で内蔵またはシステムを選択でき、変更は保存後の次回起動からリポジトリ操作へ反映します。  
設定には選択中と次回起動時のモード、各構成要素のバージョン、パス、検証結果を表示します。  

システムモードは`/opt/homebrew/bin`、`/usr/local/bin`、`/usr/bin`の順でGit、Git LFS、Git Flowを個別に検出します。  
システムモードでGitを実行するときは、検出済み構成要素のディレクトリを先頭に置いたうえで、利用者のログインシェルから取得した`PATH`をGitフックとヘルパーにも使用します。  
`PATH`の取得はアプリの起動時に一度だけ行い、2秒以内に取得できない場合は`/opt/homebrew/bin`、`/usr/local/bin`、`/usr/bin`、`/bin`、`/usr/sbin`の固定パスで操作を継続します。  
変更を反映するにはアプリを再起動します。  
開発起動中にネイティブ側が再ビルドされた場合、古いバックエンドは次の操作を実行せず「更新があります。アプリを再起動してください。」と表示します。  
配布用ビルドではこの開発用判定を行いません。  
内蔵モードは利用者のシェルを参照せず、同梱したツールチェーンとOS標準コマンドだけを使用します。  
Gitを検出できない構成は選択できません。  
Git LFSまたはGit Flowだけがない場合は、その構成要素を必要とする機能だけを停止します。  
内蔵ツールチェーンのチェックサムが一致しない場合や必要なファイルがない場合もアプリは起動し、リポジトリ操作を停止した状態でシステムモードへ切り替えられます。  

### Git Flow

Git Flowの操作画面は現在公開しません。  

### Git LFS

`.gitattributes`の`filter=lfs`を検出し、クローン、チェックアウト、マージ、リベース、プル、ステージ、コミットで、選択中のツールチェーンにあるGit LFSフィルターを透過的に使用します。  
Git LFS対象ファイルのステージとステージ解除は、フィルターを確実に適用するためファイル全体で行い、行単位操作は利用できません。  
通常のプッシュでは、Gitの参照を送る前に対象参照のLFSオブジェクトをアップロードします。  
全ローカルタグをプッシュする場合は、現在のブランチと全ローカルタグから到達できるLFSオブジェクトを先にアップロードします。  
利用者の共通Git設定とフックは変更しません。  
システムモードでGit LFSを検出できない場合、LFSリポジトリの操作をポインターファイルのまま続けず、必要な構成要素を示して停止します。  
追跡、追跡解除、ロック、移行の専用画面は設けません。  

### リポジトリ情報の変更とリモートURLの復旧

フェッチ、プル、プッシュの失敗は、リモート不在、認証失敗、接続失敗、その他のGit失敗へ分類します。  
確実に分類できる最初の3種類だけを一覧の「リモートを確認」「認証を確認」「接続を確認」へ反映し、リモート名、原因、失敗日時だけを場所ごとに保存します。  
URL、Git出力、認証情報は警告として保存せず、同じリモートへの対応操作が成功したときだけ警告を解除します。  

リポジトリ一覧と開いているリポジトリの切替画面から、リポジトリ情報を変更できます。  
画面には「リモート」と「ローカル」のタブを表示し、初期状態では「リモート」を選択します。  
「リモート」タブでは、既存リモートのすべてのフェッチURLとプッシュURLを変更できます。  
リモートがない場合だけURL入力欄を表示し、保存時に`origin`として追加します。  
「ローカル」タブでは表示名とローカルパスを変更できます。  
リモート情報の取得に失敗しても、ローカル情報だけの保存は行えます。  
ローカルパスの変更は移動済みのリポジトリへ登録をつなぎ直す操作として扱い、既存の場所変更確認を経て、表示名とリモートURLの変更も新しい場所へ引き継ぎます。  
フェッチURLとプッシュURLは最初から入力欄で表示し、変更分をまとめて保存します。  
保存時は変更前URLを実行直前に再照合し、失敗した変更で停止して最新URLを再読み込みします。  
先に成功した変更は巻き戻しません。  
フェッチURLを変更した場合は、保存完了後に対象リモートごとに1回フェッチします。  
`origin`を追加した場合も、設定を読み直して追加結果を確認した後に1回フェッチします。  
保存中に`origin`が追加済みとなった場合は、最新状態を読み直して保存を停止します。  
フェッチ失敗時も新しいURLを保持して警告を残します。  
`origin`の追加後とプッシュURLの変更後は自動でプッシュせず、次の明示的なプッシュ成功まで警告を残します。  
リモートURLの変更はローカルGit設定だけを変更し、リモート側の状態は変更しません。  

## 対象外

次のGit機能およびホスティングサービス固有の機能は対象外です。  

- GitHubまたはGitLab固有の連携
- 認証情報の管理
- スタッシュ
- 注釈付きタグ、タグの削除、個別タグのプッシュ
- `origin`以外のリモートの追加、リモートの削除、名称変更
- 対話形式のリベース
- `--force`による無条件の強制プッシュ
- サブモジュール
- 作業ツリー管理

次の配布および運用機能は対象外です。  

- App Sandbox
- Developer ID署名
- 公証
- Mac App Storeでの配布
