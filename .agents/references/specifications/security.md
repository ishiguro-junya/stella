# セキュリティ

このリファレンスは、アプリの脅威モデル、信頼境界、安全性保証、機密情報、依存関係、例外方針の正本です。  
利用者から見える安全上の動作は[プロダクト仕様](product.md#安全性)、内部構造は[アーキテクチャ](architecture.md)、検査の選び方は[テスト](../workflows/testing.md)、署名鍵を使う公開操作は[リリース](../workflows/release.md)を参照してください。  
検査コマンドの構成、脆弱性例外の現行一覧、公開手順はこのリファレンスに複製しません。  

## 脅威モデルと信頼境界

開いたリポジトリのファイル名、内容、Git設定、Git出力、フックは信頼しません。  
フロントエンドからTauri Coreへ渡る要求を権限境界とし、Rust側で操作、入力、パス、現在状態を検証します。  
リポジトリとその外側、アプリとGitプロセス、アプリと更新配布元、開発環境と公開用の署名鍵を別の信頼境界として扱います。  
依存パッケージ、静的検査ルール、脆弱性情報は外部から取得するため、取得失敗や検証不能を安全とは判定しません。  

## 安全性保証

- macOSアプリはアドホック署名で配布し、`codesign --verify --deep --strict`でアプリバンドル全体の署名整合性を検査できますが、配布元の本人性、Appleによる検査、公証は保証しません。
- Tauriコマンドはメインウィンドウだけに許可し、フロントエンドへシェル、ファイルシステム、プロセスの各プラグインを公開しません。
- メインウィンドウの表示操作だけを`main`ウィンドウへ許可し、起動先のDOM確定後に自己表示する用途へ限定します。
- Tauri Dialogプラグインには`open`コマンドだけを許可し、ローカルリポジトリとクローン先のディレクトリ選択にだけ使用します。
- Gitは絶対パスと引数配列で起動し、シェルを介しません。
- 読み取り用の差分では外部差分と`textconv`を無効にします。
- 信頼しないリポジトリ内容による資源消費を抑えるため、[プロダクト仕様](product.md#差分表示)の軽量表示上限と、[アーキテクチャ](architecture.md#差分表示とファイル編集)のハード上限を適用します。
- ハード上限で切り詰めた差分は先頭部分を含む本文、`DiffSurface`、画像候補、画像プレビューを生成せず、レンダラーへ本文を渡しません。
- 大きな履歴コミットでは集約した本文を破棄し、完全なファイル一覧だけを許可してから個別差分を遅延取得します。
- ファイル一覧は完全な標準出力であること、厳密なNUL区切り、UTF-8、Gitの状態、パスを検証し、不完全または不正な入力を受け入れません。
- 個別差分にも同じハード上限と切り詰め判定を適用し、超過したファイルの本文と画像解析だけを拒否します。
- Gitのパスは引数配列と検証済みのリポジトリ内相対パスで扱い、コミットとファイルの識別子および画像解析のハッシュを再検証します。
- 確認トークンはリポジトリ、世代、操作全体、プレビューの要約値へ結合し、有効期間を短くして1回だけ使用できるようにします。
- 書き戻し対象は対象ツリーと現在の索引から列挙し、未追跡内容も含めてプレビューの要約値を作ります。
- 利用者由来のパスを受けるGitコマンドは、共通オプションの`--literal-pathspecs`を指定します。
- 活動を保存する前にコマンド出力から機密情報を除去し、上限内に切り詰め、環境変数と標準入力を保存対象から外します。
- Git出力の解析器は安全判定に使う各結果へ上限を設け、上限超過をエラーとして扱います。
- CSPはリモートスクリプトを許可せず、差分ワーカーに必要な`worker-src 'self' blob:`だけを追加します。
- 更新ファイルは組み込みの公開鍵で署名を検証し、利用者が確認した場合だけインストールします。

## 機密情報、ログ、証跡

秘密鍵、アクセストークン、パスワード、環境変数、標準入力をリポジトリ、活動、検査証跡へ保存しません。  
エラーや検査結果を共有するときは秘密の生値を除き、検出器、ファイル、行、指紋、影響、終了状態だけを残します。  
TruffleHogは外部検証と自動更新を無効にし、現在のファイルとGit履歴の検査結果を`tmp/security/`のSARIFへ保存します。  
SARIFには秘密の生値ではなく、検出器、場所、検証状態、秘密から作った一方向の指紋だけを含めます。  
資格情報の除去を検証する既存テスト資料は、`.trufflehog-allowlist`に記録したSARIF指紋と完全一致する場合だけ許可します。  
許可した指紋の追加、削除、変化も失敗とし、意図したテスト資料かを再確認して許可リストを更新します。  

## 依存関係と検査ツール

直接依存と開発ツールは、広く利用され継続的に保守されているものを採用し、`package.json`、`Cargo.toml`、`mise.toml`でバージョンを固定します。  
更新時は公式の安定版、変更内容、既知の脆弱性、推移依存、配布物への混入を確認します。  
セキュリティ検査は自動修正を行わず、検出結果を確認してから依存更新またはコード修正を行います。  
OxlintとClippyは`mise run lint`で実行するため、セキュリティ専用タスクでは重複実行しません。  

## セキュリティ検査

検査の選択、コマンド、外部通信は[テスト](../workflows/testing.md#セキュリティに影響する変更を検査する)と`mise.toml`を正本とします。  

## 失敗と警告の判定

検出結果、検査エラー、ルールや脆弱性情報の取得失敗、パッケージ署名の異常、許可リスト外の秘密、期限切れの例外を失敗として扱います。  
本番依存の高リスク以上、期限付き例外に含まれない新規脆弱性、関連する未解決警告がある状態では完了または公開と判定しません。  
通信を必要とする検査が通信できない場合は未検証であり、合格として扱いません。  
誤検知を除外する場合も、対象、理由、影響、失効日を記録し、検査全体を無効にしません。  

## 脆弱性例外

例外の機械可読な正本は`osv-scanner.toml`とし、識別子、理由、失効日を必須とします。  
例外の対象と期限は同ファイルを参照し、親依存の更新時または失効日前に解消状況を再確認します。  
TruffleHogの許可対象は`.trufflehog-allowlist`を正本とし、生値ではなくSARIF指紋だけを保持します。  
許可した指紋の追加、削除、場所の変化は再確認します。  

## 公開用の署名鍵

自動更新用の秘密鍵とキーチェーンのパスワードはリポジトリ外で管理し、検査、ログ、証跡へ含めません。  
鍵の準備、署名、成果物の確認、公開操作は[リリース](../workflows/release.md)に従います。
